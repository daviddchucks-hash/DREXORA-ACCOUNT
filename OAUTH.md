# Drexora Identity & Single Sign-On (SSO) Developer Guide

Welcome to the **Drexora Account Identity Provider (IdP)** documentation. Drexora Account provides a standards-compliant **OAuth 2.0** and **OpenID Connect (OIDC)** authentication service enabling applications (both internal Drexora products and external third-party applications) to authenticate users securely via "Continue with Drexora".

---

## 🔑 Key Identity Concepts

1. **Immutable User Sub ID (`sub`)**:
   Every user in Drexora Account has a permanent, immutable Drexora User ID starting with `dx_` (e.g., `dx_8f72abc123`). This identifier remains unchanged even if the user changes their primary email address.
2. **PKCE (Proof Key for Code Exchange)**:
   PKCE (`S256`) is required for public clients (Single Page Apps, Mobile, Desktop) and strongly recommended for confidential server-side applications to protect against authorization code interception attacks.
3. **Exact Redirect URI Matching**:
   Redirect URIs provided during authorization requests must match one of the client's registered redirect URIs byte-for-byte. Wildcards or arbitrary client-supplied URLs are strictly rejected.

---

## 🚀 Application Registration

Currently, third-party application self-service registration is controlled by Drexora. Registered applications receive:

* `clientId`: A unique client identifier (e.g., `dx_client_a1b2c3d4e5f6`).
* `clientType`: `public` (browser/mobile) or `confidential` (backend servers).
* `appType`: `drexora_product` or `external_application`.
* `redirectUris`: An explicit list of allowed redirect URIs.
* `allowedScopes`: Permitted access scopes (e.g., `openid profile email`).

## 📡 OAuth 2.0 / OIDC Endpoints Overview

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `/oauth/authorize` | `GET` | Initiates user authorization flow with optional PKCE and consent screen. |
| `/oauth/token` | `POST` | Exchanges authorization code for Access Token and signed OIDC ID Token. |
| `/oauth/userinfo` | `GET` | Returns authenticated user profile claims based on granted scopes. |
| `/oauth/revoke` | `POST` | Revokes an access token (RFC 7009 compliant). |

## 1. Authorization Endpoint

### `GET /oauth/authorize`

Redirects the user to Drexora Account for authentication and consent.

#### Query Parameters

| Parameter | Required | Type | Description |
| :--- | :--- | :--- | :--- |
| `client_id` | **Yes** | `string` | The registered application Client ID. |
| `redirect_uri` | **Yes** | `string` | The target callback URL (must match a registered redirect URI). |
| `response_type` | **Yes** | `string` | Must be `code`. |
| `scope` | **Yes** | `string` | Space-separated requested scopes (e.g., `openid profile email`). |
| `state` | **Yes** | `string` | Opaque string generated by client to prevent CSRF attacks. |
| `code_challenge` | **Required for Public** | `string` | Base64url encoded SHA-256 hash of `code_verifier`. |
| `code_challenge_method` | No | `string` | PKCE transformation method. Default: `S256`. |

#### Example Authorization Request

```http
GET /oauth/authorize?client_id=dx_client_test_app&redirect_uri=https%3A%2F%2Fexample.com%2Fcallback&response_type=code&scope=openid%20profile%20email&state=xyz123&code_challenge=E9Mel-2ugpFuUYWGf6upFmS4bPPGP8n9AXwB1A36XY8&code_challenge_method=S256 HTTP/1.1
Host: api.drexxora.name.ng
```

#### Successful Redirect Callback

Upon user authentication and consent, Drexora Account redirects back to the registered `redirect_uri`:

```http
HTTP/1.1 302 Found
Location: https://example.com/callback?code=dx_code_8f72abc123456789&state=xyz123
```

## 2. Token Endpoint

### `POST /oauth/token`

Exchanges the authorization code for an Access Token and OIDC ID Token.

#### Request Headers

```http
Content-Type: application/json
```

#### Request Body Parameters

| Parameter | Required | Description |
| :--- | :--- | :--- |
| `grant_type` | **Yes** | Must be `authorization_code`. |
| `code` | **Yes** | The single-use authorization code received from `/oauth/authorize`. |
| `redirect_uri` | **Yes** | The exact `redirect_uri` used in the initial authorization request. |
| `client_id` | **Yes** | The registered Client ID. |
| `client_secret` | **Confidential Clients** | The secret assigned to confidential server clients. |
| `code_verifier` | **PKCE Clients** | The original raw PKCE verifier string used to generate `code_challenge`. |

#### Example Token Exchange Request

```json
POST /oauth/token HTTP/1.1
Host: api.drexxora.name.ng
Content-Type: application/json

{
  "grant_type": "authorization_code",
  "code": "dx_code_8f72abc123456789",
  "redirect_uri": "https://example.com/callback",
  "client_id": "dx_client_test_app",
  "code_verifier": "dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk"
}
```

#### Successful Token Response

```json
HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: no-store

{
  "access_token": "dx_at_9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4d",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "openid profile email",
```

## 3. UserInfo Endpoint

### `GET /oauth/userinfo`

Retrieves user identity claims for the authenticated user based on granted scopes.

#### Request Headers

```http
Authorization: Bearer dx_at_9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4d
```

#### Example UserInfo Response

```json
HTTP/1.1 200 OK
Content-Type: application/json

{
  "sub": "dx_8f72abc123",
  "name": "Jane Doe",
  "email": "jane.doe@example.com",
  "email_verified": true
}
```

---

## 4. Token Revocation Endpoint

### `POST /oauth/revoke`

Revokes an active access token so it can no longer be used.

```json
POST /oauth/revoke HTTP/1.1
Host: api.drexxora.name.ng
Content-Type: application/json

{
  "token": "dx_at_9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4d"
}
```

#### Response

```json
HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "success",
  "message": "Token revoked successfully"
}
```

## 🛡️ Supported Scopes & Claims

| Scope | Granted Claims | Description |
| :--- | :--- | :--- |
| `openid` | `sub` | Required for OpenID Connect identity token & subject ID. |
| `profile` | `name` | User's full name. |
| `email` | `email`, `email_verified` | Primary email address and verification flag. |

## ⚠️ OAuth Error Standard

Errors follow the standard OAuth 2.0 specification (RFC 6749):

| Error Code | HTTP Status | Description |
| :--- | :--- | :--- |
| `invalid_request` | 400 | Missing or invalid parameters (e.g. unregistered `redirect_uri`). |
| `invalid_client` | 400 / 401 | Invalid `client_id` or `client_secret`. |
| `invalid_grant` | 400 | Expired, reused, or invalid authorization code or PKCE verifier. |
| `invalid_scope` | 400 | Requested scope is not permitted for this application. |
| `unauthorized_client` | 400 | Client is disabled or unauthorized. |
| `access_denied` | 403 | User denied consent or user account is suspended/disabled. |
