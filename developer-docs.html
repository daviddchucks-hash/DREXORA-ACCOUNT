Developer Integration Documentation

Learn how to authenticate users with "Continue with Drexora" using OAuth 2.0 & OpenID Connect (OIDC).

1. Introduction

Drexora Account functions as a centralized identity provider (IdP). Every user has a permanent, immutable Drexora User ID starting with dx_ (e.g. dx_8f72abc123).

Applications authenticate users using the standard Authorization Code Flow with PKCE (Proof Key for Code Exchange).

3. API Endpoints Reference

A. Discovery Endpoint

GET /.well-known/openid-configuration

OpenID Connect configuration document advertising endpoints and capabilities.

B. Authorization Endpoint

GET /oauth/authorize

Initiates user login and consent screen.

Parameter Type Description
client_id Required Your registered Client ID (e.g. dx_client_123456)
redirect_uri Required Must match one of your registered redirect URIs exactly
response_type Required Must be code
scope Required Space-separated scopes: openid profile email
state Required Cryptographically random string to prevent CSRF
code_challenge Required (Public) Base64url encoded SHA-256 hash of PKCE verifier
code_challenge_method Optional Defaults to S256

C. Token Exchange Endpoint

POST /oauth/token

Exchanges the single-use authorization code for Access Token and OIDC ID Token.

POST /oauth/token HTTP/1.1
Host: api.drexxora.name.ng
Content-Type: application/json

{
  "grant_type": "authorization_code",
  "code": "dx_code_123456789",
  "redirect_uri": "https://yourapp.com/callback",
  "client_id": "dx_client_123456",
  "code_verifier": "dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk"
}

D. UserInfo Endpoint

GET /oauth/userinfo

Returns authenticated user claims based on granted scopes.

GET /oauth/userinfo HTTP/1.1
Host: api.drexxora.name.ng
Authorization: Bearer dx_at_9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4d

Response:
{
  "sub": "dx_8f72abc123",
  "name": "Jane Doe",
  "email": "jane.doe@example.com",
  "email_verified": true
}

4. Security Guidelines

  • Exact Redirect Matching: Wildcards are strictly prohibited. The redirect_uri parameter must match your registered URI character-for-character.
  • PKCE Protection: Always use PKCE (S256) to protect against code interception.
  • Client Secret Protection: Never expose client secrets in client-side HTML or JavaScript. Confidential clients must execute token exchanges on secure backend servers.
  • Immutable User Identifier: Always key local user records to sub (the permanent Drexora User ID starting with dx_), never to email address.
